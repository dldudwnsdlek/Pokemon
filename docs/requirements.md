# 요구사항 정의서 — 이박사의 연구노트 (포켓몬 RAG 서비스)

AI 코어 프로젝트 2회차 · RAG 기반 도메인 지식 서비스

## 1. 도메인 확정과 조건 충족 근거

**도메인: 포켓몬 (관동지방 1세대, 전국도감 1~151번)**

| 조건 | 충족 근거 |
|---|---|
| 항목 메타데이터 약 100건 이상 | PokéAPI(`https://pokeapi.co/api/v2/`)에서 1세대 **151마리**. 인증 키 없이 무료. 한국어 이름·분류·도감 설명·타입·특성·키·몸무게·능력치·진화 계통 제공 → `data/pokemon.json` 151건 |
| 외부 문서 출처와 이용 조건 | ① 한국어 위키백과 (MediaWiki API, **CC BY-SA 4.0**) ② PokéAPI 타입 상성·진화 데이터를 문장으로 바꾼 "구조화 문서"(무료 공개 API, 공정 이용 규칙) — 출처 종류가 2가지라 F2016도 충족. 자세한 내용은 `SOURCES.md` |
| 근거 없이 답하면 틀리는 질문 3개 이상 | 아래 대표 질문 6개. 진화 조건, 세대별 타입 상성, 공식 분류명, 정확한 몸무게처럼 기억으로 답하면 틀리기 쉬운 사실 |
| 위험 도메인 여부 | **해당 없음**(게임·애니메이션). 면책 문구 대신 세대별 차이가 있는 답에 "게임 버전에 따라 내용이 다를 수 있어요" 안내 |

### 대표 질문 (검증·F2015 비교에 계속 재사용)

정답은 구현 중 실제 데이터(`data/*.json`)와 대조해 확정했습니다.

| # | 질문 | 왜 근거가 필요한가 | 데이터 기준 정답 |
|---|---|---|---|
| Q1 | 이브이는 1세대에서 무엇으로 진화하고, 조건은 무엇인가? | 이후 세대의 진화형(에브이·블래키 등 5종)과 섞어 답하기 쉬움 | 샤미드(물의돌)·쥬피썬더(천둥의돌)·부스터(불꽃의돌) |
| Q2 | 리자몽은 드래곤 타입인가? | 외형 때문에 흔히 틀림 | 아니다. 불꽃/비행 |
| Q3 | 고스트 타입 기술은 에스퍼 타입에게 효과가 어떤가? | 1세대와 이후 세대의 상성이 다름 | 현재 2배, **1세대에서는 효과 없음(0배)** |
| Q4 | 팬텀은 어떻게 진화하나? | 통신교환이라는 특수 조건 | 고오스 →(레벨 25) 고우스트 →(통신교환) 팬텀 |
| Q5 | 뮤츠의 분류는 무엇인가? | 한국어 공식 분류명은 기억으로 맞히기 어려움 | 유전포켓몬 |
| Q6 | 잠만보의 몸무게는? | 정확한 숫자는 지어내기 쉬움 | 460kg |

범위는 1세대만 다룹니다. 그 밖의 포켓몬은 "이 노트는 관동지방 1세대(1~151번) 포켓몬만 다뤄요"라고 안내합니다.

## 2. 기능적 요구사항

| 번호 | 분류 | 요구사항명 | 요구사항 상세 | 우선순위 | 구현 |
|---|---|---|---|---|---|
| F2001 | 데이터 | 항목 메타데이터 로드 | 151마리를 로드하고, 1마리를 이름·도감번호·분류·타입·특성·키·몸무게·능력치·진화·구분·도감 설명이 이어진 하나의 텍스트로 구성 | 필수 | `data_prep/fetch_pokeapi.py`, `build_item_text.py` |
| F2002 | 색인 | 메타데이터 색인(RAG 1) | 항목 텍스트를 임베딩해 `pokemon_meta`에 색인. 청크 ID `pkm:{도감번호}` 고정 + upsert로 다시 돌려도 151 유지. 화면 상단에 색인 건수 항상 표시 | 필수 | `store/indexer.py`, `scripts/build_index.py` |
| F2003 | 프롬프트 | 검색어 추출(프롬프트 1) | "30년 연구한 포켓몬 연구가" 역할로 검색어를 JSON 배열로 추출. 선택한 포켓몬 이름은 항상 첫 검색어로 강제 | 필수 | `rag/collector.py` |
| F2004 | 수집 | 외부 문서 수집(프롬프트 2) | 위키백과 검색 후보(제목·요약)를 선별 프롬프트로 골라 본문·원문 주소 수집. 포켓몬 자체 문서는 선별·길이 규칙보다 우선해 항상 포함. 수집한 검색어는 다시 수집하지 않음. 오프라인 모드(`collect.offline`) 지원 | 필수 | `rag/collector.py`, `data_prep/wiki_source.py` |
| F2005 | 색인 | 외부 문서 색인(RAG 2) | 본문을 청크 크기 800·중복 150(설정값)으로 잘라 `pokemon_docs`에 색인. 청크 ID `{포켓몬ID}:{문서ID}:{순번}` | 필수 | `store/indexer.py` |
| F2006 | 검색 | 근거 검색 및 병합 | 선택 포켓몬 메타데이터 청크는 검색 없이 항상 1번. 외부 문서는 그 포켓몬 문서 + 공용 문서 범위에서 Top-k(설정값 5) 검색. 같은 ID·같은 본문 앞 200자 중복 제거 | 필수 | `rag/retriever.py` |
| F2007 | 생성 | 근거 기반 답변(프롬프트 3) | LangGraph `retrieve → generate` 두 노드. 근거만 사용, 없으면 "제공된 자료에서는 확인되지 않습니다". 근거마다 출처 종류(도감 데이터/위키백과/PokéAPI 자료) 구분 | 필수 | `rag/graph.py` |
| F2008 | 생성 | 근거 표시 | 답변의 `[근거 n]`을 정규식으로 찾아 실제 인용된 근거만 제목·출처·원문 링크와 함께 표시. 인용 0개면 안내 | 필수 | `rag/citations.py`, `web/js/chat.js` |
| F2009 | UI | 항목 선택 및 질의응답 | 도감 색인·탐색 카드·풀숲에서 포켓몬 선택. 대화 기록은 포켓몬별로 따로 저장 | 필수 | `web/js/state.js`, `streamlit_app.py` |
| F2009-1 | UI | 자유 질문 (F2009 확장) | 포켓몬을 고르지 않고도 질문. 질문에 포켓몬 이름이 있으면 그 포켓몬을 고른 것처럼 처리(여러 마리면 모두 근거에 포함), 없으면 질문과 가까운 도감 데이터 3마리 + 범위 제한 없는 문서 검색. 자유 질문 문서는 따로 저장해 포켓몬별 검색에 섞이지 않음. 기록도 따로 저장 | 추가 | `rag/graph.py`, `data_prep/name_match.py`, `rag/retriever.py` |
| F2010 | 서비스 | 도메인 특화 기능 | ① 배틀 상성 코치(유리/불리/비슷함 판정 + 타입 상성 근거) ② 진화 안내(계통 그림 + 조건 설명). 둘 다 근거 표시 | 필수 | `features/battle_coach.py`, `evolution_guide.py` |
| F2011 | 서비스 | 조건 기반 항목 탐색 | 자연어 조건 → 규칙 필터(타입·전설·환상·숫자) → 의미 검색 15마리 → 선별 프롬프트 C로 조건을 모두 만족하는 것만 카드로 제시. 카드를 누르면 그 포켓몬 대화로 | 필수 | `features/finder.py`, `data_prep/finder_terms.py` |
| F2012 | UI | 진행 상태 및 안내 | 수집·생성 중 진행 기록 표시, 색인 없음·키 없음·결과 없음·외부 호출 실패 안내 | 필수 | `web/js/ui.js`, `services/errors.py` |
| F2013 | UI | 프론트엔드 직접 구현 | 순수 HTML·CSS·JS 화면 + FastAPI 서버 분리, 요청·응답 형식 정의, SSE로 진행 상태 전송 | 심화 | `web/`, `api/server.py` |
| F2014 | 검색 | MMR 검색 적용 | `search_type: mmr`(fetch_k 30, lambda 0.5). 유사도/MMR 근거 비교 화면과 스크립트 | 심화 | `rag/retriever.py`, `/api/compare-search` |
| F2015 | 품질 | RAG 전후 품질 비교 | 대표 질문 6개를 RAG 없이/RAG로 답하고 사실 정확성·근거 제시·모름 인정으로 비교 | 심화 | `scripts/compare_rag.py` → `docs/rag_comparison.md` |
| F2016 | 수집 | 여러 문서 출처 결합 | 위키백과(서술형, 청킹) + PokéAPI 구조화 문서(짧아서 1청크). 근거에 출처 종류 도장 | 심화 | `data_prep/structured_docs.py` |
| F2017 | 서비스 | 연구소 놀이터 | 첫 화면 아래로 스크롤하면 나오는 놀이 공간: ① 풀숲에서 몬스터볼로 잡기 + 내 도감 151칸(브라우저 저장) ② 실루엣·울음소리 퀴즈 ③ 포켓몬과 이야기하기(도감 데이터만, 프롬프트 TALK) ④ 진화 장면 애니메이션 ⑤ 성격 테스트(프롬프트 PERSONA). 근거 번호가 붙는 RAG 답변이 아님을 화면에 안내 | 추가 | `web/js/playground.js`, `meadow.js`, `evoshow.js`, `features/playground.py` |

## 4. 가이드와 다르게 정한 점 (사용자 확인 또는 기술적 이유)

| 항목 | 가이드 | 실제 | 이유 |
|---|---|---|---|
| User-Agent | "SSAFY 교육 프로젝트" (한글) | "SSAFY education project" | HTTP 헤더에는 영문(ASCII)만 넣을 수 있어 한글이 들어가면 요청 자체가 실패함 |
| 포켓몬 자체 위키 문서 찾기 | 이름과 제목이 같은 문서 | 이름이 동음이의어 문서면 "이름 (포켓몬)" 문서 사용, 목록 표로만 연결되면 "단독 문서 없음"으로 기록 | "팬텀"은 동음이의어 문서, "꼬렛"은 표만 있는 "1세대 포켓몬 목록"으로 연결됨 (`docs/wiki_coverage.md`) |
| `--reset-docs` | 컬렉션을 비우고 수집 캐시 초기화 | 컬렉션을 비우고 **저장해 둔 위키 본문을 새 청크 설정으로 다시 잘라 넣음**. 수집 기록까지 지우려면 `--forget-collected` | 같은 문서로 청크 수만 비교해야 V06(청크 크기 변경 전후)을 정확히 볼 수 있음 |
